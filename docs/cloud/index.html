What it would be

Hosted, not hollowed out.

The hard constraint on the whole design is that it stays the same product. The same Loom, the same Cortex workers, the same APIs and the same pipelines — with the database, the storage, the upgrades and the GPUs someone else's problem.

  • One database per customer The design is isolation by tenancy, not multi-tenancy inside the server. Your library is a database, and it is yours.
  • Bring your own hardware limits Processing is the expensive part. A hosted pool has to be honest about what it costs, and about where your media sits while it is being read.
  • The exit is part of the design Anything you can do in Cloud you can do on a machine in your office, because it is the same software. Leaving means moving data, not rewriting integrations.
  • It changes nothing about the open source build No capability moves out of the Apache 2.0 platform to make a hosted plan look better. That rule is written down on the Studio page and it covers this one.

The plan

What is being designed.

None of this is running. It is listed so the shape of the offer is public while it is still being argued about.

Provisioned libraries

A control plane that stands up a Loom instance and its database per customer, on the same Helm charts the self-hosted deployment uses.

Processing on tap

A shared pool of GPU workers running the same Cortex node kinds, so transcription and face detection do not need a machine of your own.

Identity that federates

Sign in with your own identity provider rather than with another set of credentials, on the OAuth2 support Loom already has.

Storage and backup

Object storage for the binaries, with the retention and backup story a hosted service has to have and a self-hosted install can choose to skip.

Metering that you can audit

If a hosted plan is billed by what it processed, the number has to be inspectable. That is a design requirement, not a feature.

Operated, and visible

The same Prometheus metrics the self-hosted build exposes, surfaced to you rather than kept behind an operations team.

Commitments

What will be true of it.

These are the constraints the design is being held to. They are here to be quoted back at us.

Same software
Cloud runs the open source platform. If a fix is needed to make hosting work, it lands in the open source build.
Your data is yours
Exportable through the same REST and GraphQL APIs you would use to put it there, without asking anyone.
No feature hostages
Nothing is removed from the self-hosted build to make the hosted one more attractive. Not now, not later.
Self-hosting stays first class
The documentation, the charts and the containers are for running it yourself, and that will not become the neglected path.
Honest about location
Where the media sits and which models see it will be stated plainly, per region and per node kind.
No sign-up theatre
There is no waiting list product and no form collecting addresses for a launch email. When there is something to try, this page will say so.
